# 제조 이미지 이상 탐지 비교 실험

정상 데이터만으로 불량품을 탐지할 수 있을까? 이 질문에서 출발해, 사전학습 특징 추출기를 사용하는 PatchCore를 기준 모델로 구성했습니다. 이후 입력 해상도와 정상 특징 저장 비율을 바꾸고, 정상 이미지로 처음부터 학습한 오토인코더와 비교했습니다.

불량품을 정상으로 판정해 놓치는 경우를 줄이는 데 중점을 두고 Recall을 우선 평가했습니다. 정상은 0, 불량은 1로 정의하며, 정상 상품의 오탐에 따른 재검사 비용도 살펴보기 위해 Precision, F1, 정상 오탐률을 함께 확인했습니다.

## 연구 질문과 개선 가설

| 연구 질문 | 실험에서 확인한 방법 |
|---|---|
| 불량 학습 이미지가 부족할 때 정상 데이터만으로 불량을 탐지할 수 있을까? | 정상 이미지의 특징을 저장하고 새로운 이미지와의 차이를 계산하는 PatchCore 사용 |
| 사전학습 PatchCore의 불량 검출률을 더 높일 수 있을까? | 기준 조건에서 한 번에 하나씩 입력 해상도와 특징 저장 비율 변경 |
| 우리 정상 이미지로 처음부터 학습한 모델은 어떤 성능을 보일까? | CNN 오토인코더를 MSE 복원 손실로 학습하고 복원 오차로 이상 판단 |

입력 크기를 224×224에서 384×384로 높이면 리사이즈 과정에서 사라질 수 있는 작은 결함 정보를 더 유지할 수 있을 것으로 예상했습니다. 특징 저장 비율을 1%에서 10%로 늘리면 정상 특징을 더 풍부하게 보관할 수 있을 것으로 예상했습니다. 두 가설을 각각 독립된 비교 조건으로 평가했습니다.

## 평가 설계

MVTec AD의 15개 상품에 네 가지 조건을 적용해 총 60개 실험을 수행했습니다. 상품마다 정상 학습 데이터의 80%로 모델을 구성하고 20%를 정상 검증에 사용했으며, 동일 상품의 비교 조건들은 같은 학습·검증·테스트 분리를 사용했습니다. 테스트 이미지와 라벨은 최종 지표 계산에 사용했습니다.

각 모형의 **정상 검증 이상 점수 95백분위수**를 해당 모형의 판정 임계값으로 정했습니다. 모형마다 점수 척도가 달라 실제 임계값 수치는 다르지만, 임계값을 정하는 규칙은 동일합니다. **임계값을 의도적으로 낮춰 성능 변화를 비교하는 시나리오는 진행하지 않았습니다.**

학습과 평가는 이미지 단위 정상·불량 구분을 대상으로 합니다. 불량 종류별 분류나 불량 위치의 정확도는 이번 평가 범위에 포함하지 않았습니다.

## 결과와 해석

아래 수치는 이번 단일 실행에서 얻은 상품별 지표의 평균입니다. 각 상품에 동일한 가중치를 부여했으며, 불량 누락 수는 전체 테스트 이미지에서 발생한 건수의 합계입니다.

| 비교 조건 | AUROC | Precision | Recall | F1 | 정상 오탐률 | 불량 누락 수 |
|---|---:|---:|---:|---:|---:|---:|
| 기준 PatchCore · 224×224 · 특징 1% | 0.9768 | 0.9510 | 0.9443 | 0.9449 | 0.1408 | 86 |
| PatchCore · 224×224 · 특징 10% | 0.9818 | 0.9410 | 0.9613 | 0.9483 | 0.1720 | 68 |
| PatchCore · 384×384 · 특징 1% | **0.9875** | 0.9498 | **0.9802** | **0.9636** | 0.1502 | **30** |
| 처음부터 학습한 오토인코더 · 224×224 | 0.5900 | 0.7822 | 0.2413 | 0.3217 | 0.1456 | 985 |

### 입력 해상도 증가

384×384 조건은 기준보다 평균 Recall이 약 **3.59%포인트** 높았고, 전체 불량 누락이 **86건에서 30건**으로 줄었습니다. 특히 screw의 누락은 27건에서 3건으로 감소했습니다. 이번 실험에서는 해상도를 높이는 방법이 불량 누락 감소에 가장 큰 개선을 보였습니다.

다만 cable은 Recall이 0.9348에서 0.8696으로 낮아졌으며, 전체 평균 정상 오탐률도 0.1408에서 0.1502로 증가했습니다. 모든 상품에서 같은 효과가 나타난 것은 아니므로 상품별 결과와 함께 해석해야 합니다.

### 특징 저장 비율 증가

특징 저장 비율을 10%로 늘리면 기준보다 평균 Recall이 약 **1.70%포인트** 높아졌고, 불량 누락이 **86건에서 68건**으로 줄었습니다. 반면 정상 오탐률은 0.1408에서 0.1720으로 증가했고 Precision은 0.9510에서 0.9410으로 낮아졌습니다.

불량을 덜 놓치는 효과는 있었지만, 정상품을 불량으로 판정하는 비용이 함께 늘어났습니다. 따라서 이 조건의 성능이 모든 측면에서 나아졌다고 단정하기는 어렵습니다. 실제 적용에서는 불량 유출 비용과 정상 재검사·폐기 비용을 함께 고려해야 합니다.

### 처음부터 학습한 오토인코더

정상 이미지의 복원 손실은 감소했지만 평균 Recall은 0.2413으로 낮았습니다. 현재 구성에서는 정상 이미지를 잘 복원하도록 학습하는 것만으로 불량 검출 성능을 확보하기 어려웠습니다. 다만 PatchCore와 구조·학습 목적·이상 점수 계산 방식이 함께 달라지므로, 이 결과를 사전학습 유무만의 효과로 해석할 수는 없습니다.

원본 지표는 [전체 결과 JSON](../outputs/model_comparison_all.json), 상품별 60개 결과와 평균 표는 [DataFrame 노트북](../outputs/model_comparison_table.ipynb)에 보관했습니다.

## 한계와 후속 검토

- **단일 실행의 한계**: 실험을 한 번 진행했으므로 초기화, 특징 선택, 데이터 분리에 따른 변동성을 평가하지 못했습니다. 반복 실험으로 평균과 편차를 확인할 필요가 있습니다.
- **오탐과 누락의 교환 관계**: Recall 개선과 함께 정상 오탐이 증가했습니다. 운영 비용을 정의하지 않은 상태에서 특정 설정이 항상 더 우수하다고 결론 내리기 어렵습니다.
- **상품별 차이**: 평균 지표의 상승이 모든 상품의 개선을 의미하지는 않습니다. 작은 결함, 질감, 정상 이미지의 다양성 등 상품별 특성과 결과를 함께 분석해야 합니다.
- **모형 비교의 범위**: 오토인코더는 사전학습 유무뿐 아니라 구조와 학습 방식도 달라, 사전학습의 효과를 분리한 통제 실험에 해당하지 않습니다.
- **평가 데이터의 한계**: 테스트 결과를 관찰하며 개선 방향을 탐색했습니다. 선택한 설정의 최종 일반화 성능을 확인하려면 별도 평가 데이터가 필요합니다.

후속 방안으로 **판정 임계값을 낮추는 시나리오**를 검토할 수 있습니다. 불량을 더 많이 검출할 가능성이 있지만, 정상품을 불량으로 판정하는 오탐과 재검사 부담이 커질 수 있습니다. 이번에는 이 시나리오를 실행하지 않았습니다. 향후 이를 실험한다면 추가 검증 데이터에서 임계값을 선택하고 독립된 평가 데이터로 Recall과 정상 오탐률을 함께 확인해야 합니다.

| 파일 | 역할 |

| `evaluate.py` | 실험 조건, 모델 호출, 검증 임계값, 테스트 지표, 평균 DataFrame, 실행 기록 |

## 환경과 실행

현재 확인 환경은 Windows, Python 3.13.15, CPU입니다. 프로젝트 루트(`project1`의 상위 폴더)에서 실행합니다.

```powershell
python -m pip install -r project1/requirements.txt
python -m project1.evaluate --summary-only
```

데이터는 루트의 `mvtec_anomaly_detection/상품명/{train,test}` 구조로 준비합니다.
첫 실행 시 사전학습 가중치를 다운로드할 수 있습니다. 가중치 태그는 `wide_resnet50_2.racm_in1k`로 고정했습니다.

새 결과를 별도 경로에 기록해 평가하려면 다음 명령을 사용합니다.

```powershell
python -m project1.evaluate --product bottle --result-path outputs/refactored_bottle.json
python -m project1.evaluate --result-path outputs/refactored_all.json
```

중단 후 동일한 경로와 조건에 `--resume`을 붙여 실행합니다.

```powershell
python -m project1.evaluate --resume --result-path outputs/refactored_all.json
python -m project1.evaluate --summary-only --result-path outputs/refactored_all.json
```

## 실험 조건

| 이름 | 모델 | 입력 크기 | coreset |
|---|---|---|---|
| baseline | 사전학습 PatchCore | 224×224 | 1% |
| memory_10pct | 사전학습 PatchCore | 224×224 | 10% |
| size_384 | 사전학습 PatchCore | 384×384 | 1% |
| autoencoder | 무작위 초기화 CNN 오토인코더 | 224×224 | 해당 없음 |

`evaluate.py`의 상단 상수에서 조건을 관리합니다. 오토인코더는 Adam, 학습률 0.001, MSE, 최대 20 epoch, patience 3, min_delta 0.00001을 사용하고 가장 좋은 가중치를 복원합니다.

상품별 `train/good`의 80%는 학습, 20%는 정상 검증에 사용합니다. 기존 `test`는 평가에 사용합니다.
정상 검증 이상 점수의 95백분위수를 임계값으로 정합니다. 입력은 RGB, ImageNet 평균·표준편차 정규화이며, 현재 비교 지표는 이미지 단위입니다.

평균 DataFrame은 상품별 동일 가중치로 집계합니다. `delta_recall`은 같은 상품 기준 모델 대비 Recall 차이입니다. 임계값 자체는 모형마다 점수 척도가 달라 직접 비교하지 않습니다.

## 재현성과 결과 관리

- Python, NumPy, PyTorch와 CUDA 난수 및 결정적 연산 설정을 고정합니다. DataLoader는 독립된 seed 42 기반 생성기를 사용합니다.
- 새 실행은 결과 JSON과 함께 `.meta.json`에 조건, 패키지 버전, 코드 해시, 분리된 경로·라벨·파일 크기·수정 시각의 서명을 기록합니다. 서명은 픽셀 내용의 해시 검사는 아닙니다.
- 부분 결과의 `--resume`은 기록이 같은 경우에만 진행합니다. 기존 결과 파일을 새 실행으로 덮어쓰려면 새 `--result-path`를 지정합니다.
- 이전 형식의 완료된 결과는 `--summary-only`로 조회할 수 있습니다. 실행 기록이 없는 부분 결과는 새 실행과 섞지 않습니다.
- 기존 60개 결과와 노트북은 과거 실험 기록입니다. 이전 실행은 모든 난수원과 DataLoader 순서를 고정하지 않았으므로 리팩터링 후 숫자가 달라질 수 있습니다.
- 다른 하드웨어, 패키지 버전, 데이터 변경에서는 동일한 수치를 보장하지 않습니다. 성능 안정성 판단에는 여러 seed의 반복 실험이 필요합니다.
